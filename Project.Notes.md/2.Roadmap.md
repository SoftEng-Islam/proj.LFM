# LFM — Linux File Manager: Roadmap & TODOs

A modern, fast, customizable, and keyboard-driven file manager for Linux built with Vue.js, TypeScript, and Tauri.

---

## Core Goals

- Linux-first experience
- High performance and low memory usage
- Keyboard-driven workflow
- Modular and extensible architecture
- Fully customizable interface
- Native desktop integration
- Privacy-focused and offline-friendly
- Modern UI/UX with advanced productivity tools
- Declrative configuration support

## Configuration System

### Persistent Configuration

Path: `~/.config/LFM/`

- [ ] TOML configuration files
- [ ] User preferences
- [ ] Themes
- [ ] Keybindings
- [ ] Layout persistence

### Cache System

Path: `~/.cache/LFM/`

- [ ] Thumbnail cache
- [ ] Temporary metadata cache
- [ ] Session recovery data
- [ ] Background task state
- Cached data must be safely recoverable
- Cache cleanup tools must be included

The implementation tasks for the LFM TOML-based configuration system.

### Rust Backend

- [ ] Add `serde`, `serde_json`, and `toml` dependencies to `src-tauri/Cargo.toml`
- [ ] Create a `Config` struct with `Serialize` and `Deserialize` derives
- [ ] Implement config path resolution via `tauri::api::path::config_dir()` to locate `~/.config/LFM/config.toml`
- [ ] Load config on startup and fall back to hardcoded defaults when the file is missing
- [ ] Detect read-only filesystem cases and log a warning instead of failing when save is not possible
- [ ] Persist a default `config.toml` when a missing file is detected and writing is available
- [ ] Expose Tauri IPC commands `get_config` and `save_config`

### Frontend Integration

- [ ] Call `get_config` on application mount using `@tauri-apps/api/tauri`
- [ ] Create a settings UI view for toggling configuration options
- [ ] Save changes only when the user explicitly confirms, avoiding unnecessary disk writes
- [ ] Keep the frontend type-safe and consistent with existing Vue/TypeScript project rules

### Configuration Schema

- [ ] Support `appearance` settings: `theme`, `font_size`, `show_hidden_files`
- [ ] Support `behavior` settings: `default_path`, `confirm_delete`, `single_click_open`
- [ ] Support `terminal` settings: `emulator`

### Notes

- Use TOML because it is readable, Rust-native, and matches NixOS/Home Manager patterns.
- Keep the implementation Linux-only and follow the project rules in `Project.Notes.md/2.Rules.md`.

## Performance Goals

- Fast startup time
- Low RAM usage
- Smooth navigation
- Async filesystem operations
- Efficient thumbnail generation
- Minimal CPU usage while idle
- Support caching.

---

## Architecture Goals

- Modular codebase
- Feature-based structure
- Strong TypeScript typing
- Reusable composables
- Separation of concerns
- Scalable plugin architecture

---

## Non-Goals

The project will NOT support:

- Windows-specific features
- macOS-specific integrations
- Electron
- Heavy telemetry
- Mandatory cloud accounts
- Closed-source dependencies where avoidable

---

> **Note:**
> Even though the frontend uses Vue.js, this project must behave like a native Linux desktop application — not like a traditional web application.
> Desktop UX behavior must take priority over browser-default behavior whenever conflicts occur.
