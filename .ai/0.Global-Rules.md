# Global AI Development Rules

## Rule Priority Order

When rules conflict, follow this order:

1. Explicit user instructions
2. Project architecture and safety rules
3. Existing codebase conventions
4. Framework best practices
5. General preferences in this document

## Core Principles

- Preserve existing behavior unless explicitly instructed otherwise.
- Prefer maintainability over cleverness.
- Avoid unnecessary abstractions and overengineering.
- Keep files focused and small when practical.
- Prefer modular and composable architecture.
- Avoid rewriting unrelated code.
- Avoid CDN and Stuff that needs to be online.
- Use the packages in packages.json.

## Refactor Boundaries

Do not:

- rename unrelated files
- move directories unnecessarily
- rewrite working code for style reasons
- format unrelated files

## Dependency Rules

Before adding a dependency:

1. Check native APIs first.
2. Check existing packages first.
3. Prefer lightweight libraries.
4. Avoid overlapping dependencies.

## AI Rules

- Do not hallucinate APIs or files.
- Ask for clarification when uncertain.
- Prefer extending existing architecture.
- Keep generated code consistent with project style.

## Investigation Workflow

Before implementing a feature or fixing a bug:

1. Read all related files completely.
2. Trace the full data flow:

   - UI
   - composables
   - stores
   - services
   - IPC
   - Rust backend
3. Identify existing utilities before creating new ones.
4. Identify whether logic already exists in another feature.
5. Prefer extending existing architecture over replacing it.
6. Document uncertainty before making architectural assumptions.

Do not start implementation after reading only a single file.

## Filesystem Safety Rules

All filesystem operations must:

1. Avoid destructive behavior by default.
2. Validate paths before operations.
3. Handle symbolic links safely.
4. Avoid blocking the UI thread.
5. Support cancellation when possible.
6. Report meaningful errors to the frontend.
7. Preserve file metadata when appropriate.
8. Avoid accidental recursive operations.

Never trust frontend paths directly without validation.

## IPC and Backend Ownership Rules

Frontend responsibilities:

- rendering
- interaction
- temporary UI state
- animations
- view logic

Rust/Tauri responsibilities:

- filesystem operations
- process management
- native integrations
- privileged operations
- performance-heavy tasks

Do not duplicate business logic across frontend and backend.

Prefer strongly typed IPC contracts.
